# AI Landscape — Quick Reference

> **Goal:** Remember what each concept is and where it fits.
> Think of the landscape as: **Models → Training → Inference → Context → Agents → Safety → Evaluation**

---

## 1. AI Foundations

### 3. Artificial Intelligence (AI)

The broad field of making machines perform tasks that normally require human intelligence.
Includes reasoning, perception, planning, learning, language, and decision-making.

### 4. Machine Learning (ML)

A subset of AI where systems learn patterns from data rather than being explicitly programmed for every rule.
Examples: classification, prediction, recommendation.

### 5. Neural Networks & Deep Learning

Neural networks learn complex patterns through layers of interconnected mathematical functions.
**Deep Learning** = neural networks with many layers, powering modern vision and language models.

### 6. Large Language Models (LLMs)

Large neural networks trained primarily on massive amounts of text to understand and generate language.
Examples include GPT, Claude, Gemini, Llama.

### 7. Small Language Models (SLMs)

Smaller language models optimized for lower cost, latency, memory, or local deployment.
Usually trade some capability for efficiency.

### 8. Vision Language Models (VLMs)

Models that understand both **visual and textual information**.
Can analyze images, screenshots, diagrams, documents, etc.

### 9. Multimodality

A model/system working across multiple modalities such as **text, image, audio, video, and code**.
VLMs are one example of multimodal AI.

### 10. Frontier Models

Highly capable models representing the current leading edge of AI capabilities.
Usually large, expensive models developed by major AI labs.

### 11. Artificial General Intelligence (AGI)

A hypothetical level of AI capable of broadly performing intellectual tasks across domains at roughly human-level or beyond.
There is no universally agreed definition or established test for AGI.

# 2. How Models Work

### 12. Parameters & Weights

**Parameters** are learned numerical values inside a model.
**Weights** commonly refers to those learned values; more parameters ≠ automatically better model.

### 13. Tokens

The units of text that models actually process.
A token can be a word, part of a word, punctuation, or other text fragment.

### 14. Tokenizers & Tokenization

Tokenization converts raw text into tokens that the model can process.
Different models use different tokenization schemes.

### 15. Context Window

The maximum amount of information a model can consider in one request/conversation.
Includes input, conversation history, retrieved data, and sometimes output.

### 16. Context

The information supplied to a model to help it produce the current response.
**Prompt + history + retrieved information + tool results = context.**

### 17. Temperature & Sampling

Controls how the model selects its next token.
Lower temperature → more deterministic; higher → more varied/random outputs.

### 18. Mixture of Experts (MoE)

A model contains multiple specialized **experts**, but only some are activated for each input.
Allows very large models while reducing computation per request.

# 3. Training & Model Adaptation

### 19. Training vs. Inference

**Training:** teach model parameters using data.
**Inference:** use the trained model to generate predictions/responses.

### 20. Pre-Training vs. Post-Training

**Pre-training:** learn broad patterns from huge datasets.
**Post-training:** improve behavior, instruction following, reasoning, safety, etc.

### 21. Fine-Tuning

Further train an existing model on a smaller, specialized dataset.
Used to adapt behavior, style, domain knowledge, or task performance.

### 22. LoRA & Parameter-Efficient Fine-Tuning

Instead of modifying all model parameters, train a small set of additional parameters.
**LoRA** makes fine-tuning much cheaper and more memory-efficient.

### 23. Synthetic Data

Data generated by AI/models rather than collected directly from humans or real-world sources.
Useful for training, augmentation, testing, and specialized datasets.

### 24. RLHF

**Reinforcement Learning from Human Feedback** uses human preferences to improve model behavior.
Humans provide feedback → model is optimized toward preferred responses.

### 25. Distillation

Train a smaller **student model** to reproduce useful behavior of a larger **teacher model**.
Goal: retain capability while reducing cost and latency.

### 26. Data Poisoning

Attack where malicious or incorrect data is inserted into training/fine-tuning data.
Can intentionally influence model behavior.

### 27. Reasoning Models

Models optimized to spend additional computation on complex problems before producing an answer.
Useful for coding, mathematics, planning, and multi-step reasoning.

---

# 4. Inference & Optimization

### 28. Caching

Reuse previously computed results instead of processing the same information again.
Reduces latency and cost.

### 29. Quantization

Represent model parameters using lower numerical precision, such as FP16, INT8, or INT4.
Reduces memory and often improves inference speed at some potential quality cost.

### 30. Model Routing

Send different requests to different models based on requirements.
Example: **small/cheap model for simple tasks → powerful model for complex tasks.**

---

# 5. Prompt & Application Layer

### 31. Prompts

Instructions and information given to a model to produce an output.
They define what the model should do and what information it should use.

### 32. Prompt Engineering

Designing prompts to consistently obtain better model behavior.
Focuses on instructions, examples, constraints, and output requirements.

### 33. Context Engineering

Designing **everything placed into the model's context**, not just the prompt.
Includes history, retrieved documents, tools, memory, state, and instructions.

### 34. Structured Outputs

Require the model to return data in a predefined structure such as JSON or a schema.
Useful when AI output must be consumed reliably by software.

### 35. APIs for AI Models

Interfaces allowing applications to call AI models programmatically.
Typically send input/context → model processes it → application receives output.

---

# 6. Agents

### 36. Models vs. AI Agents

A **model** generates predictions/responses.
An **agent** uses a model plus tools, context, state, and a loop to accomplish a goal.

### 37. AI Agents

Software systems that can reason about a task, choose actions, use tools, observe results, and continue working.
The model is the reasoning engine; the surrounding system provides capabilities.

### 38. Tools

External capabilities an agent can invoke.
Examples: APIs, databases, search, code execution, browsers, file systems.

### 39. The Agent Loop

Typical cycle: **Observe → Reason → Choose action → Use tool → Observe result → Repeat**.
Stops when the goal is completed or requires human intervention.

### 40. The Harness

The infrastructure surrounding the model that controls execution.
Handles prompts, tools, permissions, state, retries, limits, validation, and orchestration.

---

# 7. Knowledge & Context

### 41. Hallucinations

When a model produces information that sounds plausible but is incorrect or unsupported.
A fundamental limitation of probabilistic generation.

### 42. Grounding

Connecting model responses to trusted external information or data.
Goal: make answers based on verifiable sources rather than model knowledge alone.

### 43. RAG

**Retrieval-Augmented Generation:** retrieve relevant information first, then give it to the model as context.
Common pattern: **Query → Retrieve → Context → Generate**.

### 44. Vector Databases & Embeddings

**Embeddings** convert data into numerical vectors representing semantic meaning.
Vector databases efficiently find semantically similar information for retrieval/RAG.

### 45. Memory

Information retained and reused across interactions or tasks.
Can include conversation history, user preferences, facts, or agent state.

### 46. Compaction

Compressing older/large context into a smaller summary or representation.
Allows long-running agents to continue without exceeding the context window.

### 47. Context Rot

As context becomes extremely large, the model may become less effective at using all of it.
**More context ≠ automatically better context.**

---

# 8. Modern Agent Infrastructure

### 48. Model Context Protocol (MCP)

A standardized protocol for connecting AI applications/models to external tools and data sources.
Think: **standard interface between agents and capabilities.**

### 49. Agent Skills

Reusable capabilities/instructions that teach an agent how to perform a particular type of task.
Think of them as modular expertise an agent can load when needed.

### 50. Computer Use

Allows an AI system to interact with a computer UI using actions such as clicking, typing, scrolling, and reading screens.
Extends agents beyond APIs into GUI-based workflows.

### 51. Sandboxes

Isolated environments where agents can safely execute code or perform potentially risky operations.
Limits what an agent can access or damage.

### 52. Agentic Search

Search where the AI doesn't simply return search results but **iteratively searches, evaluates, follows leads, and synthesizes information**.
Useful for complex research tasks.

### 53. Human in the Loop

A human reviews, approves, corrects, or takes over important agent actions.
Useful for high-risk or irreversible decisions.

### 54. Agentic Engineering

Engineering software around autonomous/semiautonomous AI agents rather than treating AI as a simple API call.
Focuses on tools, state, permissions, loops, evaluation, reliability, and observability.

### 55. Vibe Coding

Using AI to generate and modify software primarily through natural-language instructions.
Fast for prototyping, but generated code still requires engineering review and testing.

---

# 9. Evaluation & Security

### 56. Benchmarks

Standardized datasets/tests used to compare model capabilities.
Examples measure coding, reasoning, mathematics, knowledge, etc.

### 57. Evals

Tests designed to determine whether an AI system behaves correctly for a **specific use case**.
Benchmarks measure general capability; evals measure whether *your system works*.

### 58. Prompt Injection

Malicious or unintended instructions embedded in user input or retrieved content that attempt to manipulate the model.
Example: a document telling an agent to ignore its original instructions.

### 59. Data Exfiltration

Unauthorized extraction or transmission of sensitive data by an AI system or attacker.
Particularly important for agents with access to files, databases, email, or APIs.

### 60. Open-Weights & Open-Source Models

**Open-weights:** model parameters are publicly available, allowing local/self-hosted inference.
**Open-source** has a broader meaning involving source/code, data, licenses, and reproducibility.

### The 10-second mental model

**AI** is the big field → **ML** learns from data → **Deep Learning** uses neural networks → **LLMs/VLMs** are modern foundation models → **Training** creates/adapts models → **Inference** uses them → **Context/RAG/Memory** give them information → **Tools + loops turn models into Agents** → **MCP/Skills/Harness** provide agent infrastructure → **Evals + Security** make the system reliable and safe.
